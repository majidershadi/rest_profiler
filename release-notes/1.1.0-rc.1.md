# REST Profiler for Splunk 1.1.0-rc.1

This prerelease adds encrypted request-body storage and selective body-secret
masking for REST profiles.

## Highlights

- The complete saved **Body** field is now encrypted at rest through UCC and
  Splunk secure storage (`passwords.conf`), using the same supported platform
  mechanism as the existing password and token fields.
- Wrap sensitive body fragments in section signs, such as
  `{"username":"§api-user§","password":"§change-me§"}`.
- Preview shows marked values as `********`; live sends remove the section
  signs and transmit the original values.
- `§§` produces a literal section sign. An unmatched marker stops composition
  with an error that never echoes the request body.
- Returned request metadata now masks configured custom token headers in
  addition to `Authorization` and `Proxy-Authorization`.

## Security boundary

The marker is a display-time control, not a custom encryption scheme. The
entire body is encrypted at rest, including unmarked content. Markers select
which fragments must also be hidden when a user previews the composed request.
Decryption and marker removal occur only inside `splunkd` while composing a
live request.

Existing authentication secrets continue to use Splunk secure storage. No
secret value is written to release artifacts, logs, previews, or response
events.

## Compatibility and upgrade note

- Packaged app version: `1.1.0`
- GitHub prerelease tag: `v1.1.0-rc.1`
- Existing profiles remain readable. Because the Body field is now encrypted,
  edit and save an existing profile once to migrate any previously stored body
  into secure storage.
- Back up `$SPLUNK_HOME/etc/apps/rest_profiler/local/` before upgrading and
  restart Splunk after installation.
