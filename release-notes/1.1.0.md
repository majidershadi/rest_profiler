# REST Profiler for Splunk 1.1.0

Version 1.1.0 adds encrypted request-body storage and selective body-secret
masking for REST profiles.

## Highlights

- The complete saved **Body** field is encrypted at rest through Splunk secure
  storage (`passwords.conf`), using the same supported platform mechanism as
  password and token fields.
- Wrap sensitive body fragments in section signs, for example
  `{"username":"§api-user§","password":"§change-me§"}`.
- Preview renders marked values as `********`. Live requests remove the section
  signs and transmit the original values.
- Use `§§` when the outgoing body requires a literal section sign. An unmatched
  marker stops request composition without echoing the body.
- Configured custom token headers, `Authorization`, and `Proxy-Authorization`
  are masked in preview and returned request metadata.

## Security boundary

The marker controls preview visibility; it is not a custom encryption scheme.
The complete saved body is encrypted at rest, including unmarked content.
Decryption and marker removal occur only inside `splunkd` while composing a
live request.

## Upgrade notes

- Existing profiles remain readable. Edit and save an existing profile once to
  migrate a previously stored body into encrypted secure storage.
- Back up `$SPLUNK_HOME/etc/apps/rest_profiler/local/` before upgrading.
- Install the new package over the existing app and restart Splunk.
