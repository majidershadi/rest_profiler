# REST Profiler for Splunk 1.0.1

This is a Splunk Cloud compatibility and release-engineering patch. It does not change REST profile behavior or stored configuration.

## Highlights

- Refreshes the UCC-managed `appserver/templates/base.html` static bootstrap to the current build-time cache-busting format.
- Resolves the Splunk Cloud vetting notification for `check_for_custom_mako_templates` caused by the 1.0.0 bootstrap generated with an older UCC release.
- Updates the release toolchain to Splunk UCC Framework 6.5.3 and Splunk AppInspect 4.3.0.
- Restores `package/app.manifest` and `package/lib/requirements.txt` to Git; the generic Python `.gitignore` had excluded both required build inputs.
- Adds deterministic release checks and a GitHub Actions workflow that creates the GitHub Releases entry from a `v*` tag.

## Important changes

- Version metadata is updated consistently to `1.0.1`.
- No saved-profile schema, REST endpoint, alert-action parameter, custom search command, or secret-storage migration is introduced.
- Existing `$SPLUNK_HOME/etc/apps/rest_profiler/local/` content remains compatible.

## Upgrade note

Back up the app's `local/` directory, install `rest_profiler-1.0.1.tar.gz` over 1.0.0, and restart Splunk. Existing local configuration and encrypted credentials are preserved by the normal Splunk app-upgrade process.

## Validation

The release workflow runs repository/package consistency checks and `splunk-appinspect inspect` before publishing. Splunkbase will run its own current AppInspect evaluation after upload.
